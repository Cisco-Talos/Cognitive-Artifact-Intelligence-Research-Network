## Notes on recurring noise patterns

**Pulsar RAT (Win32:Pulsar-A):** Fody-packed .NET RAT. Fires on T1-Codegen_Residue and T1-Prompt_Residue because Fody-merged assemblies include AI library string tables. Cluster is tight (all named Client.exe, detection range 33–52). Confirmed cluster 57 in 2026-07-03 run; same samples also appeared in clusters 32, 39, 77, 95, 141, 164 across earlier runs.

**Implosions.exe (MSIL/RedLine + Zusy/Themida):** Two co-named families sharing the `Implosions.exe` filename — a .NET RedLine credential stealer (50+ samples, Jan 2023 – Jul 2026) and a Themida-packed Zusy spreader (12 samples). Both appear in `llmgate-hunt` results — likely due to WMI behavioral strings (`calls-wmi` tag) and sysupdsvc-adjacent process naming picked up in sandbox output. Neither has any AI integration. Forms multiple small clusters on re-run; all hashes in `dead_end_hashes.txt` for complete suppression.

**T3-HONESTCUE_LLM_Probe_Loader FP vectors (flagged 2026-07-15):** The rule condition uses bare OR across all strings, creating two FP pathways: (1) `$honestcue = "HONESTCUE"` fires on AV detection names after any engine labels a sample Trojan.MSIL.HONESTCUE.SM — subsequent AV engines copy the label regardless of binary content; (2) `$stage2_class = "class named 'Stage2'"` / `$stage2_class2` — "Stage2" is generic .NET malware naming, not HONESTCUE-specific. Analysis of 28 cluster 147 samples (2026-07-01 run): all 28 fired on `$honestcue` (AV label propagation); 26 fired on `$stage2_class`; only 2 had `$aitask_prompt` (the Mandiant-documented HONESTCUE probe). Rule needs a stricter condition requiring `$aitask_prompt` or `($csharp_compile AND $gemini_api)` for high confidence attribution, not just AV label presence.

**Mal/SillyFDC-K (.mp3 PE) pattern:** VB6-compiled USB worm (Sophos/ZoneAlarm: Mal/SillyFDC-K; TrellixENS: Generic VB.b). PE executables with `.mp3` extension submitted from `C:\Users\user\Desktop\<RANDOM>.mp3` paths — social engineering naming. Shared imphash `6d5d84d2f024a2d1`. T1-Prompt_Residue fires on `$you_are = "You are"` matching `"unless you are sure it is not malicious.\n.#LOCALIZATION"` — this is a Windows Security Center dialog string bundled in the VB payload as a fake alert UI, not an AI prompt. First seen cluster 114 (Jul 2025 burst + Mar 2026 singleton). Also appears in cluster 171's generic spreader (Gen:Variant.jaik). The `#LOCALIZATION` localization-key format is the diagnostic marker — real AI prompts don't use this.

**Cluster 171 — XMRig coinminer + MSIL/Barys stealers + Win32/Neshta file infector:** Three distinct malware families co-clustered; 44 samples spanning 2025-07-30 to 2026-07-02. XMRig sub-group has UPX/corrupt/overlay/64bits tags (TrendMicro: Coinminer.Win64.MALXMR). MSIL/Barys/Reline sub-group: .NET credential stealers dropped to `C:\Windows\<random>.exe` paths (Kaspersky: HEUR:Trojan-PSW.MSIL.Reline.gen). Neshta sub-group: `PE_NESHTA.A` file infector — same FP mechanism as Win32/Expiro: infected host binary retained `api.openai.com/authchatgpt_ac` string table, triggering T1-LLM_API_Endpoint and T1-AI_Brand_PE_Resource. Fourth sub-group (spreader, Gen:Variant.Application.jaik): T1-Prompt_Residue fires on `"you are sure it is not malicious"` appearing in `#LOCALIZATION` context inside an infected host binary's resource strings. No AI integration in any sub-family.

**Cluster 112 — petik researcher path + Cyzt/Snojan + MSIL dictionary-word stealers:** Three co-clustered sub-families with no AI integration. All T1-Local_Model_Runtime hits are false positives: `$vllm = "vllm"` and `$gguf = "gguf"` are 4-character strings that appear as substrings in base64-like encoded payload data extracted from packed malware. Root cause of FPs; triggered T1-Local_Model_Runtime rule tightening (`.gguf` dot-prefix and `vllm.`/`import vllm` forms). petik submitter path is a known researcher collection pattern — see retraction commit f1f09c2. Cluster spans 3 representative SHA256s covering distinct cluster IDs across multiple runs.

**Win32/Expiro file infector:** Infects legitimate Windows binaries (DiagnosticsHub.StandardCollector.Service.exe, svchost, OneDriveUpdaterService.exe, etc.). Infected binaries retain original string tables. Fires on T1 rules if the host binary contained AI-adjacent strings. Forms multiple small clusters (60, 85, 82, 20, 58, 88, 23 in 2026-07-03 run) because different host binaries produce different embeddings.

**Mozilla llamafile distribution binaries + ggml-cpu DLLs (T2-Local_Inference_Deploy $llamafile FP):** `$llamafile = "llamafile" nocase` fires on: (1) Actual Mozilla llamafile release binaries (whisperfile, diffusionfile, llamafile-vulkan-arm) submitted from `home/mala/releases/0.10.x/llamafile-0.10.x/bin/` paths — legitimate Mozilla speech-to-text/inference executables; (2) Chrome and other ggml-cpu-*.dll backends that export `ggml_cpu_has_llamafile` as a CPU capability detection function. Neither category represents malware deploying llamafile. 15 affected hashes added to dead_end_hashes.txt (2026-07-16). Note: genuine malware deploying llamafile would likely appear with persistence co-occurrence or under a non-release path — consider upgrading to T2-Local_Inference_Persistence + $llamafile combo condition if this FP pattern recurs.

**SearchHelper.exe / Shareit.exe vllm FP cluster (T2-Local_Inference_Persistence $vllm bug):** 9 samples (7× SearchHelper.exe, 2× Shareit.exe), 49–64 detections, Jul 2025. Previously hit T2-Local_Inference_Persistence because the rule used bare `$vllm = "vllm"` (4-char string), which matched "vllm" as a substring in encrypted/encoded payload data within packed stealers. The persistence hit ($startup) was from "ShareIt Service" background process in sandbox — unrelated to LLM. Fix applied 2026-07-16: vllm string anchored to `"vllm."` and `"import vllm"` forms. No AI integration.

**SystemDriverUpdate.exe safetensors FP (T1-Local_Model_Runtime):** 2 samples, 36–38 detections, fake AMD driver cover story. `safetensors` match appears as a substring in the embedded string pool (possibly from a bundled component or cover strings), not from actual safetensors model loading. Behaviours show only `nexusrules.officeapps.live.com` DNS (Office telemetry); no model download, no HuggingFace contact, no inference process. Provider reference "Hugging Face" from string pool only. No AI integration.

**gugak.exe EDR recon tool (T1-Local_Model_Runtime ollama FP):** 1 sample, 38 detections, HackTool/EDR recon category. The `ollama` string match comes from the tool enumerating AI framework process names as part of its EDR/AV detection sweep — it lists ollama as a process to look for, not to deploy or use. Behaviours: no network activity, no inference process creation. No AI integration.

**FerrisScope (dzcorp/FerrisScope) — highest rule-count legitimate FP (6 rules):** Open-source Tauri/Rust Kubernetes IDE (Apache 2.0, github.com/dzcorp/FerrisScope) with a built-in AI agent supporting 6 providers (OpenAI, DeepSeek, Mistral, Ollama, Groq, Together AI). The AI agent feature directly explains all 6 rule hits: T1-LLM_API_Endpoint (provider API URLs), T1-Chinese_LLM_Provider (DeepSeek), T1-Local_Model_Runtime (Ollama localhost:11434), T2-Local_Inference_Persistence (Ollama + startup module), T2-Local_Inference_Deploy (localhost:11434), T2-Multi_Model_Provider_Cooccurrence (6 providers). Three artifacts that look suspicious but are benign: `.dpkg-new` suffix = dpkg package manager temp file naming convention during Linux package installation; `credentials.enc` = encrypted credential file from a bundled Rust dependency (headless keychain-less fallback per security policy); `ferrisscope::startup` = Tauri app autostart persistence module (user-visible setting). Two build variants both submitted 2026-07-11 (2 seconds apart) — likely automated CI/CD release pipeline uploading to VT. Main binary (`ferris-scope`) 0 detections; dpkg artifacts 2–3 heuristic detections (Kingsoft, Rising, huorong — all Linux Trojan.Agent heuristics on Tauri+Rust+AI binary). Execution parent pivot (`ferris-scope` → `ferrisscope.dpkg-new`) confirmed install chain. GitHub: 107 commits, 9 stars, active CI/CD — genuine project.

**GameHubShowcase.dll $gguf FP (T1-Local_Model_Runtime):** 2 samples (GameHubShowcase.dll 13 det + BB.exe 58 det). Delivery via `GameHubLauncher (2).rar` containing three DLLs (GameHubShowcase + GameHubUI + GameHubCore). GameHubShowcase downloads `BB.exe` from `github.com/adxc24/hihi/raw/refs/heads/main/BB.exe`, drops to `C:\Users\<USER>\AppData\Local\GameHubPro\.cache\BB.exe`, exfiltrates via `upload.gofile.io/uploadfiledata`, profiles victim via `ip-api.com`. BB.exe = `HEUR:Trojan-PSW.Win32.Disco.pefng` (Kaspersky) — Disco credential stealer (`gamehub_keys.json` target). The `$gguf` hit in T1-Local_Model_Runtime fires on a game file extension reference in the DLL's string pool (`.gguf` collision), not actual GGUF model loading. No AI integration in this campaign.

**MetaTrader 5 (terminal64.exe) T2-Local_Inference_Deploy FP:** 10 samples, all `terminal64.exe` (legitimate MetaTrader 5 trading platform binary name), first submitted 2026-07-15. T2-Local_Inference_Deploy fires on `"OPENAI_HOSTOPENAI_API_KEYOllamaopenaihttp://localhost:11434"` — MetaTrader 5 added AI/LLM assistant integration (via OpenAI-compatible API + local ollama) in recent builds (2026). The local ollama port is a configuration option for users running local AI models. Legitimate trading platform functionality; 2 heuristic-only detections (Gridinsoft + Trapmine) are FPs on a complex binary. The MetaTrader docs URLs in the string pool (`metatrader5.com/es/terminal/help/signals/signal_provider`) confirm identity.
